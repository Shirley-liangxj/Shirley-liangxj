## 项目

### 1. 小云智服 — 服饰电商 AI 售后智能客服工作台（个人项目 · 已上线）

**从 0 到 1 独立完成**：需求调研 → 方案设计 → PRD → 开发 → 部署上线 → 评测体系搭建。

**问题从哪来**：我没有停在"看别人说"。先去真实店铺当了一回买家，**实测了 5 家店、留下 11 张一手对话截图**，又抓了小红书「服饰 退货」「尺码 退货」各 22 条真实提问。两个来源指向同一件事：

> 买家的原始提问里，**大多数不是"你们的退货政策是什么"（FAQ 能答），而是"我这种情况算不算"** ——第 7 天和第 8 天退款的区别、水洗过了还能不能退、吊牌拆了算不算。**这是规则边界问题，不是知识问题。**

**我的判断**：竞品（店小蜜 / 飞鸽 / 京小智 / 七鱼）已经全量大模型化了，所以差异不在"能不能读文档"，在**两件它们结构上不做的事**：

| | 平台官方工具 | 第三方客服系统 | 小云智服 |
|---|---|---|---|
| 目标 | 帮你成交（会劝买家别退货） | 让坐席更高效（按坐席收费） | **不出错** |
| 跨平台 | 不做（帮竞品做客服＝资敌） | 做，但重 | 做 |
| 检索过程 | 黑盒，看不到它选了哪条 | 可视，但重 | **可点开溯源** |

**方案**：RAG 检索增强 + FastAPI + SQLite + 智谱 GLM，三层风控——
① **Prompt 层**：资料里没有就说不知道，不许编；
② **阈值层**：置信度低于 0.6 不硬答，转人工（这个 0.6 是扫出来的，同时看"误转人工"和"漏转人工"两个互相打架的指标）；
③ **溯源层**：每条回答能点开看依据来自哪段资料。

**自迭代**：AI 答不了的转人工，人工回复后可标进知识库，下次同类问题 AI 自己答——**系统会越用越准**。

**成果**：覆盖 80% 高频售后咨询场景；首条响应由人工 3 分钟降至秒级；搭建 67 题评测集做消融对比（裸模型 vs RAG）。

### 2. 客参谋 — AI 销售助手（企业项目 · 仓库因保密未公开）

负责**话术推荐**与**跟进计划**两个模块：需求调研 → PRD → 原型 → 跟进开发 → 收集试用反馈。

- **需求不是拍的**：从 2100 通销售录音里分层抽样 52 通（TOP 20% / 中位 / 末位各一组）逐句标注，再从 5200 条 CRM 里筛出 800 条有效记录——先搞清楚"好销售到底怎么做"，再决定系统该推荐什么。
- **关键判断**：推荐强度做成**强弱两档**（阈值 0.70–0.75 弱提示 / 0.75–0.85 强提示），而不是一刀切。因为推得太硬销售会无视，推得太软等于没有。
- **结果**：话术点击率 **40% → 75%**；新人上手周期 **3 个月 → 6–8 周**；经历 3 轮销售团队试用迭代（5–8 人 → 15–20 人 → 30+ 人）。
- 方案：Agent + Function Calling + 智谱 GLM。

> 仓库为前公司项目，**代码不公开**；可面谈时展示 PRD、原型与标注样例。

### 3. 行旅智助 — 企业差旅 AI Agent（企业项目 · 仓库因保密未公开）

面向中小企业的对话式差旅智能体：**对话式预订 + 差标自动校验 + 报销单生成**。

- 设计了 **9 个可调用工具**，并把它们分成两类，这是整个方案的核心判断：
  - **查询类**（查航班、查差标、查订单）→ 允许 Agent **自主调用**；
  - **写操作类**（下单、改签、生成报销单）→ **必须弹确认卡，人工点过才执行**。
- 理由：**"ChatGPT 是帮你想，企业 Agent 是帮你做——而'做'必须有边界。"** 订错一张机票是真花钱，生成一张超标报销单是一次合规事故。
- 内置三级差标权限校验，不同职级走不同规则。
